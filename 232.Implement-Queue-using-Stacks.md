# Implement Queue using Stacks (LeetCode 232)

## 1. Intuition

A Queue follows the **FIFO (First In, First Out)** principle, whereas a Stack follows the **LIFO (Last In, First Out)** principle.

In this problem, we need to implement a Queue using only Stack operations. To achieve this, we use **two stacks**: `st` and `st2`.

The first stack, `st`, is used to store the elements normally. Whenever we need to perform `pop()` or `peek()`, we move all elements except the last one from `st` to `st2`. This exposes the oldest element, which is the front of the Queue. After performing the operation, we move the elements back from `st2` to `st`.

This allows us to maintain the FIFO behavior of a Queue using two Stacks.

### Why did I choose this approach?

- It implements Queue behavior using only Stack data structures.
- It uses two stacks to reverse the order of elements when required.
- It maintains the FIFO (First In, First Out) behavior of a Queue.
- It is simple to understand and directly follows the Queue operations.

## 2. Approach

### Algorithm

1. Initialize two stacks:
   - `st` — used to store the Queue elements.
   - `st2` — used temporarily during `pop()` and `peek()` operations.

2. **Push Operation**
   - Add the new element directly to `st` using:
     ```java
     st.push(x);
     ```

3. **Pop Operation**
   - Move elements from `st` to `st2` until only one element remains in `st`.
   - The remaining element is the oldest element and represents the front of the Queue.
   - Remove and store this element.
   - Move all elements back from `st2` to `st`.
   - Return the removed element.

4. **Peek Operation**
   - Move elements from `st` to `st2` until only one element remains in `st`.
   - The remaining element is the front element of the Queue.
   - Store the element using `peek()` without removing it.
   - Move all elements back from `st2` to `st`.
   - Return the front element.

5. **Empty Operation**
   - Check whether `st` is empty:
     ```java
     return st.isEmpty();
     ```

### Time Complexity

- **`push()`**: O(1)
- **`pop()`**: O(n)
- **`peek()`**: O(n)
- **`empty()`**: O(1)

The `pop()` and `peek()` operations may need to move all elements between the two stacks.

### Space Complexity

- **O(n)**

The elements are stored across the two stacks, where `n` is the number of elements in the Queue.

## 3. Code

```java
class MyQueue {

    Stack<Integer> st;
    Stack<Integer> st2;

    public MyQueue() {
        st = new Stack<>();
        st2 = new Stack<>();
    }

    public void push(int x) {
        st.push(x);
    }

    public int pop() {
        while (st.size() > 1) {
            st2.push(st.pop());
        }

        int pop = st.pop();

        while (!st2.isEmpty()) {
            st.push(st2.pop());
        }

        return pop;
    }

    public int peek() {
        while (st.size() > 1) {
            st2.push(st.pop());
        }

        int peek = st.peek();

        while (!st2.isEmpty()) {
            st.push(st2.pop());
        }

        return peek;
    }

    public boolean empty() {
        return st.isEmpty();
    }
}
