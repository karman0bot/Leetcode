# Search in Rotated Sorted Array (LeetCode 33)

## 1. Intuition

A normal Binary Search works only on a completely sorted array. In this problem, the array is sorted in ascending order but rotated at an unknown index. Even after rotation, **one half of the array is always sorted**.

The idea is to first identify the sorted half during every iteration and then check whether the target lies within that sorted range. If it does, continue searching in that half; otherwise, search the other half. This allows us to eliminate half of the search space in every step.

### Why did I choose this approach?

- It extends the Binary Search technique to work on rotated sorted arrays.
- It avoids restoring or modifying the original array.
- It discards half of the search space in every iteration.
- It satisfies the required **O(log n)** time complexity.

---

## 2. Approach

### Algorithm

1. Initialize two pointers:
   - `left = 0` (starting index)
   - `right = nums.length - 1` (ending index)

2. While `left <= right`:
   - Find the middle index:
     ```java
     int mid = left + (right - left) / 2;
     ```

3. If `nums[mid] == target`, return `mid`.

4. Check which half is sorted:
   - **Left half is sorted** (`nums[left] <= nums[mid]`)
     - If the target lies between `nums[left]` and `nums[mid]`, search the left half by updating:
       ```java
       right = mid - 1;
       ```
     - Otherwise, search the right half by updating:
       ```java
       left = mid + 1;
       ```

   - **Right half is sorted**
     - If the target lies between `nums[mid]` and `nums[right]`, search the right half by updating:
       ```java
       left = mid + 1;
       ```
     - Otherwise, search the left half by updating:
       ```java
       right = mid - 1;
       ```

5. If the target is not found after the loop, return `-1`.

### Time Complexity

- **O(log n)**

Since half of the search space is discarded in every iteration.

### Space Complexity

- **O(1)**

Only a few extra variables are used.

---

## 3. Code

```java
class Solution {
    public int search(int[] nums, int target) {
        int left = 0, right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] == target) {
                return mid;
            }

            
            if (nums[left] <= nums[mid]) {
                if (nums[left] <= target && target < nums[mid]) {
                    right = mid - 1;
                } else {
                    left = mid + 1;
                }
            }

            else {
                if (nums[mid] < target && target <= nums[right]) {
                    left = mid + 1;
                } else {
                    right = mid - 1;
                }
            }
        }

        return -1;
    }
}
```

## Example

**Input**

```text
nums = [4,5,6,7,0,1,2]
target = 0
```

**Output**

```text
4
```

**Explanation**

- Initially, `left = 0`, `right = 6`, and `mid = 3`.
- The left half `[4,5,6,7]` is sorted, but the target `0` is not in this range, so search the right half.
- Now, `left = 4` and `right = 6`.
- The left half `[0,1]` is sorted, and the target `0` lies within this range, so search the left half.
- Finally, `mid = 4`, where `nums[mid] = 0`.
- Hence, the target is found at index **4**.
